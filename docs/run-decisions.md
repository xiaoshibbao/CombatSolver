# 局外决策

局外面板在奖励选牌、打开的商店和事件页面出现。默认只显示推荐；点击“执行推荐选择”才提交原生操作。“局外决策自动执行”开关独立于战斗全自动，并保存到设置中。自动执行在推荐出现后等待一小段时间，给玩家留出关闭开关的机会。

## 计算方式

这是离线的构筑启发式评分，**不是整局最优解、通关率或精确战损预测**。不调用外部 AI，不上传跑局。

- 奖励比较候选加入当前牌组后的变化，并把原生“跳过”作为独立候选。输出、防御、过牌、能量、成长、减益、消耗配合和力量配合采用覆盖与边际收益；已有角色过多时会稀释其他牌的抽到概率。候选读取当前升级、费用与动态变量。
- 商店对已覆盖的可见候选做有界组合搜索，同时考虑买牌、遗物、药水、删牌和保留金币。组合使用真实价格和当前金币，不把独立卡牌分数相加充当完整购物方案。每次确认只执行组合中的下一步，购买后根据新价格、库存和牌组重新计算。删牌目标来自实际可移除牌，按原生单选和确认流程执行。
- 事件按登记的效果构造候选，使用当前生命、生命上限、金币和牌组估算代价。治疗不计超出上限的部分，低生命时提高生存权重；不能用普通收益抵消已知致死代价。

面板分列牌组、生存、经济和额外条件收益；数值只在该评分模型内用于比较，不是 HP、金币的等价兑换率。

## 覆盖与执行边界

当前卡牌角色覆盖、遗物估值和事件效果以 `src/Runtime/RunDecisionCapture.cs`、`RunEventDecisionCapture.cs` 中的显式登记为准。当前事件效果合同覆盖 `SUNKEN_TREASURY` 和 `ABYSSAL_BATHS`；**尚未覆盖全部原版事件、角色构筑、遗物和药水**。未知候选标为“效果尚未完整覆盖”，不能把零分当成实际无收益。未知事件不会猜测选项效果或自动选第一项。

自动执行仅在单人且当前决策全部相关候选已覆盖时启用；共享事件继续使用原生投票。未覆盖的奖励替代项不能冒充免费跳过，满药水槽也不会自动买药水。商店中尚未建模的物品会使自动模式暂停。

执行前重新捕获当前页面、候选、牌组、生命、遗物、药水、金币和价格；状态变了则撤销旧推荐的执行资格。奖励使用原生调用方已经等待的选择任务，不重新创建任务。购买、删牌和事件选择只走原生入口。失败停止当前决策并保留原生界面，不换一个选项继续。

## 开发入口

`src/RunPlanning/RunDecisionPolicy.cs` 只处理值快照与评分；Runtime 捕获和执行；UI 只渲染 `RunDecisionView`。战斗期间不运行局外面板，隔离预战 worker 不启用玩家 UI 监控。

最小回归 `RUN-DECISIONS` 覆盖牌组响应、跳过、预算组合、未知排除、移除诅咒、低生命与设置往返，以及真实奖励页面。`RUN-DECISION-ROOMS` 使用隔离跑局验证商店和事件原生链路。两者均使用 `run-unattended-test`，指定敌人200HP、120秒超时和实例清理；命令约定见[无人测试](HEADLESS_TESTING.md)。实际执行结果与未验证项记入[开发笔记](DEVELOPMENT_NOTES.md)，这里列出入口不表示已通过。
